HU-01| Crear expediente clínico| Médico| Crear un expediente clínico| Iniciar formalmente el ciclo de vida de la información clínica de un paciente| Escenario 1: Crear expediente correctamente<br><br>Given un usuario autenticado con "ROLE_MEDICO" y un paciente registrado sin expediente activo.<br>When solicita crear el expediente.<br>Then el sistema genera un "MedicalRecordId" único, establece "Status = ACTIVE" y registra el evento de auditoría con "Outcome = SUCCESS".<br><br>Escenario 2: El paciente ya tiene un expediente activo<br><br>Given que el paciente ya tiene un expediente "ACTIVE".<br>When intenta crear otro expediente.<br>Then el sistema rechaza la operación con HTTP 409 y registra auditoría con "Outcome = FAIL".| Solo puede existir un expediente activo por paciente.
HU-02| Consultar versión vigente| Médico o Auditor| Consultar la versión vigente del expediente| Acceder al estado clínico actual autorizado| Escenario 1: Consulta autorizada<br><br>Given un expediente con versiones 1 hasta N.<br>When un usuario autorizado consulta la versión vigente.<br>Then el sistema retorna la versión con "VersionNumber = N" y registra auditoría con "Outcome = SUCCESS".<br><br>Escenario 2: Consulta sin permisos<br><br>Given un usuario sin permisos.<br>When solicita la versión vigente.<br>Then el sistema responde HTTP 403 y registra auditoría con "Outcome = FAIL".| La versión vigente corresponde al mayor "VersionNumber". El Data Concierge controla el acceso.
HU-03| Registrar nueva versión clínica| Médico| Registrar una modificación clínica como una nueva versión| Conservar íntegramente los estados anteriores del expediente| Escenario 1: Registrar actualización válida<br><br>Given un expediente "ACTIVE" cuya última versión es n.<br>When el médico registra una actualización válida.<br>Then el sistema crea la versión n + 1, conserva la versión n sin modificaciones, genera "DataHash", establece "PreviousEventHash" con el "EventHash" de la versión anterior, genera un nuevo "EventHash" y registra auditoría con "Outcome = SUCCESS".| Las versiones son inmutables desde la aplicación. No se permiten operaciones "UPDATE" destructivas sobre versiones históricas.
HU-04| Generar payload canónico determinístico| Sistema| Canonicalizar los datos utilizados en el cálculo criptográfico| Garantizar que el mismo estado produzca siempre la misma huella digital| Escenario 1: Datos lógicamente equivalentes<br><br>Given dos representaciones lógicamente equivalentes de los mismos datos clínicos.<br>When el "HashCanonicalizer" genera el payload canónico.<br>Then ambas producen exactamente la misma secuencia de bytes y generan el mismo "DataHash" SHA-512.<br><br>Escenario 2: Modificación de un campo<br><br>Given un payload canónico previamente generado.<br>When se modifica cualquiera de los campos incluidos y se recalcula el hash.<br>Then el nuevo "DataHash" es diferente.| Definir formalmente los campos incluidos, su orden, tipos de datos, representación de "null", codificación UTF-8, fechas ISO-8601 UTC y normalización de cadenas.
HU-05| Controlar concurrencia de versiones| Sistema| Controlar actualizaciones concurrentes| Evitar versiones duplicadas o bifurcaciones de la cadena de integridad| Escenario 1: Dos solicitudes concurrentes<br><br>Given que la última versión existente es n y llegan dos solicitudes concurrentes basadas en esa versión.<br>When ambas intentan crear la versión n + 1.<br>Then solamente una solicitud es confirmada, la segunda recibe HTTP 409 y no se genera una bifurcación de la cadena.| Utilizar control optimista de concurrencia, restricciones únicas o un mecanismo transaccional equivalente.
HU-06| Consultar historial clínico versionado| Médico o Auditor| Consultar el historial de versiones| Reconstruir la evolución temporal del expediente| Escenario 1: Consulta del historial autorizada<br><br>Given un expediente con versiones 1 hasta N.<br>When un usuario autorizado consulta el historial.<br>Then el sistema retorna las N versiones ordenadas ascendentemente por "VersionNumber", incluye los metadatos de creación y el estado de integridad permitidos para su rol, y registra auditoría con "Outcome = SUCCESS".| No modificar ni reconstruir retrospectivamente versiones históricas.
HU-07| Consultar auditoría| Auditor o Administrador| Consultar los eventos de auditoría| Conocer las operaciones realizadas sobre la información clínica| Escenario 1: Consulta autorizada<br><br>Given un usuario con "ROLE_AUDITOR" o un rol autorizado.<br>When consulta la auditoría.<br>Then el sistema retorna eventos con "Timestamp", "UserId", "Action", "ResourceId" y "Outcome".<br><br>Escenario 2: Consulta sin autorización<br><br>Given un usuario sin autorización.<br>When intenta consultar la auditoría.<br>Then el sistema responde HTTP 403 y el intento también queda auditado.| Registrar las operaciones exitosas y fallidas. La auditoría es independiente del historial clínico.
